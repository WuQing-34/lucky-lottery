# 幸运大转盘 —— 部署到腾讯云轻量应用服务器

目标：把抽奖系统跑在 `62.234.140.218` 上，公网可访问，参与者用手机直接打开链接就能抽奖。

## 速通版（先看这个，三分钟搞定）

**第 1 步 · 放行端口**：轻量服务器控制台 → 实例 → **防火墙** → 添加规则：协议 `TCP`、端口 `8744`、来源 `0.0.0.0/0`。

**第 2 步 · 传文件**：控制台 → 实例 → **「登录」**（打开网页终端）→ 右侧 **「文件管理器」** → 把 `lottery-deploy.tar.gz` **拖进去**。

**第 3 步 · 跑命令**（在网页终端里，**必须带 `sudo`**）：

```bash
cd ~ && tar -xzf lottery-deploy.tar.gz && sudo bash lottery-deploy/deploy.sh
```

脚本会自己检查 Docker、铺文件、构建、启动、等待健康检查，最后打印自检结果和访问地址。
**看到 `{"ok": true, ...}` 就是成了。** 然后浏览器打开 `http://62.234.140.218:8744/`。

**第 4 步 · 改密码**：登录 `http://62.234.140.218:8744/admin`（默认 `admin888`）→ 系统设置 → 改管理密码。**这步别跳。**

出问题就把终端里的输出整段发我。

## 部署方案（先说结论）

| 事项 | 结论 |
|---|---|
| 部署方式 | **Docker 单容器**（服务器上已有 Docker，且这套应用纯标准库、零依赖，镜像构建几十秒） |
| 占用端口 | **8744**（不碰你原来项目占的 8733） |
| 目录 | `/opt/lottery`（不碰 `/opt/coupon-flow`） |
| 数据 | 宿主机 `/opt/lottery/data/lottery.db`，重建容器不丢数据 |
| 需要你做的事 | 放行防火墙 8744、拖一个 tar.gz 上去、跑一条命令、**改管理密码** |

> **关于原项目**：`/opt/coupon-flow` 我不动。它和抽奖系统端口、目录、容器名全都独立，同时跑没有任何冲突。
> 你哪天确认不发券了，再单独停它（`cd /opt/coupon-flow && sudo docker compose down`）——留着当后路更稳妥。

## 步骤 1：放行端口 8744

轻量应用服务器控制台 → 你的实例 → **防火墙** → 添加规则：

```
应用类型：自定义
协议：TCP
端口：8744
来源：0.0.0.0/0
```

不加这条，容器起来了但公网打不开——**这是最容易漏的一步**。

---

## 步骤 2：把部署包传上去

1. 控制台 → 轻量应用服务器 → 实例 → 点 **「登录」**，会打开网页终端（OrcaTerm，不需要 SSH 密码）。
2. 网页终端**右侧有「文件管理器」**，把 `lottery-deploy.tar.gz` 直接**拖进去**（默认落在 `/home/<你的用户名>`）。

> ⚠️ 注意：`scp` 命令要在**你自己的电脑上**执行，不要贴到服务器终端里跑，否则报 `No such file or directory`。
> 走文件管理器拖拽最省事。

---

## 步骤 3：一条命令部署

在网页终端里执行（**要加 `sudo`**，`/opt` 属 root）：

```bash
cd ~
tar -xzf lottery-deploy.tar.gz
sudo bash lottery-deploy/deploy.sh
```

脚本会自动完成：铺文件到 `/opt/lottery` → 构建镜像 → 启动容器 → 等待健康检查 → 打印自检结果。

首次会拉取 `python:3.12-slim` 基础镜像，**大约 1~3 分钟**，期间没输出是正常的。
脚本重复执行是安全的，以后升级只要重跑它，`data/` 里的数据不会被覆盖。

## 步骤 5：改管理密码（必做，别跳）

系统是明文 HTTP，管理端密码又是一个入口。**部署完立刻做这两件事**：

1. 浏览器登录管理端 → **系统设置** → 修改管理密码，换成 12 位以上、跟其他系统不重样的一串。
2. 顺手在「系统设置」里核对 **部门编号 `1000003263`**、**标题/业务订单编号 `双节课消活动礼品`** 是否正确。

> 没改密码之前，别把公网地址发给任何人。

## 步骤 6：发给参与者

方式一（推荐）：导入名单后，给每个人单独发专属链接，打开即登录，不用手输 ID：

```
http://62.234.140.218:8744/?uid=10001
```

方式二：只发首页 `http://62.234.140.218:8744/`，让大家自己输 ID。

> **http 明文传输**：参与者填的收货人姓名、电话、地址在网络上是明文的。这批数据本身不算高敏感，
> 但要清楚这个前提。介意的话再加域名 + HTTPS（见文末）。

## 日常运维

```bash
# 看日志
sudo docker logs --tail 100 -f lottery-web

# 重启
cd /opt/lottery && sudo docker compose restart web

# 停止
cd /opt/lottery && sudo docker compose down

# 备份数据（数据库 + 管理密码配置，就这一个目录）
sudo tar -czf ~/lottery-data-$(date +%m%d).tar.gz -C /opt/lottery data

# 恢复：把 data 目录解回去后重启容器
```

**升级版本**（改了代码或功能后）：

```bash
cd ~
tar -xzf lottery-deploy.tar.gz          # 覆盖成新版
sudo bash lottery-deploy/deploy.sh      # 重跑，会自动重建镜像并重启
```

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `tar: lottery-deploy.tar.gz: Cannot open` | 文件没在当前目录。先找它：`find /home /root -maxdepth 3 -name 'lottery-deploy.tar.gz' 2>/dev/null`，找到后 `cd` 到那个目录再执行第 3 步 |
| `docker: permission denied`（或 `Cannot connect to the Docker daemon`） | 命令前忘了加 `sudo` |
| `docker compose: command not found` | 脚本会自动回退到 `docker-compose`；两个都没有才报错 |
| 公网打不开，容器是 healthy | 防火墙 8744 没放行 → 回到第 1 步 |
| 拉取 `python:3.12-slim` 卡住/失败 | 服务器上大概率**已经有了**（coupon-flow 用的就是这个基础镜像），脚本会先查本地。真没有就 `docker images \| grep python` 看现有镜像，把 `Dockerfile` 第一行 `FROM` 改成已有镜像名再重跑 |
| 页面能开，但抽奖时间和实际差 8 小时 | 时区没挂上。确认 compose 里那行 `/etc/localtime:/etc/localtime:ro` 在，然后 `sudo docker compose up -d --force-recreate web` |
| 用户端下拉框选不了省市区 | `regions.json` 没传全。`sudo docker exec lottery-web ls -l /app/regions.json` 应该能看到文件 |
| 管理端登录一直失败 | 密码改过忘了。删掉配置重启会重置为 `admin888`：`sudo rm /opt/lottery/data/config.json && cd /opt/lottery && sudo docker compose restart web`（**只重置管理密码，抽奖数据不丢**） |

## 附录：可选加固（给管理端加一层 Basic Auth）

如果你担心管理端暴露在公网，可以在应用前面加一层 nginx，只给 `/admin` 和 `/api/admin/*` 加账号密码，**用户端仍然直接打开**（参与者不受影响）。

```bash
cd /opt/lottery

# 1) 让应用只对本机暴露：把 docker-compose.yml 里的 "8744:8000" 改成 "127.0.0.1:8744:8000"
sudo sed -i 's/"8744:8000"/"127.0.0.1:8744:8000"/' docker-compose.yml

# 2) 生成账号密码（自己设，别用示例里的）
sudo mkdir -p nginx
echo "lottery:$(openssl passwd -apr1 '你的密码')" | sudo tee nginx/.htpasswd

# 3) 用叠加配置启动（应用 + nginx）
sudo docker compose -f docker-compose.yml -f docker-compose.auth.yml up -d
```

之后管理端 `http://62.234.140.218:8744/admin` 会先弹 Basic Auth 输入框（账号 `lottery`），
用户端 `http://62.234.140.218:8744/` 照旧无需密码。

> 想上 HTTPS/域名：需要备案域名 + 证书，另外配。跟我说一声，我把 nginx 那段 TLS 配置补上。
